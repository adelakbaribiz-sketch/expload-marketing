Generated by discovery audit, 2026-09-04. All counts below were re-verified directly against the current repo (not copied from `TECHNICAL_SPECIFICATION.md` without checking — that document is close but not perfectly current, e.g. it says 149 models, current schema has 150).

## What this project is

A multi-tenant, multi-language B2B marketing SaaS: lead generation, CRM, email/social/ads campaigns, SEO tooling, an AI content/negotiation/graph-agent layer, a wholesale distributor/reseller program, an internal HR/payroll module, and a payments layer (cards + crypto). Originally scaffolded on a platform providing `z-ai-web-dev-sdk` as an ambient LLM client; now runs as a standalone Next.js app with its own real multi-provider LLM aggregator layered alongside that original SDK (see ARCHITECTURE-CURRENT.md).

## Project type / languages / frameworks

- **Type**: Full-stack Next.js 16 App Router monolith (frontend + API routes in one codebase), single deployable.
- **Languages**: TypeScript (app code), Python (2 one-off translation-generation scripts under `scripts/`, not part of the running app), Shell (deploy scripts).
- **Frontend framework**: React 19 via Next.js App Router. Architecturally a **single-page app**: only two real routes exist (`src/app/page.tsx` and the newer `src/app/invite/[token]/page.tsx`); everything else is client-side view-switching inside `page.tsx`.
- **Backend**: Next.js API routes (Route Handlers) under `src/app/api/`, no separate backend service.
- **Database**: SQLite (dev) / PostgreSQL (prod, documented but not verified running) via Prisma ORM, schema-push workflow (no migration history — see KNOWN-ISSUES.md).
- **Cache/Queue**: Redis (optional, `ioredis`), with an in-memory fallback adapter for the job queue when Redis isn't configured.
- **Storage**: No object storage (S3-equivalent) integration found; file handling is limited to onboarding document parsing (PDF/DOCX text extraction) held in-memory/DB, not persisted binary storage.
- **Auth**: Custom HMAC-SHA256 signed session cookie (`src/lib/auth/simple-session.ts`), not NextAuth despite the `NEXTAUTH_SECRET` env var name.
- **Authorization**: Ad hoc per-route checks (`isSuperAdmin()`, `getCurrentUser()`, tenant-id comparison) are the actual enforcement mechanism in most routes; a formal Role/Permission RBAC system exists in the schema but is unreachable dead code in its current wiring (see DEAD-CODE.md and SECURITY-BASELINE.md).
- **Deployment**: Docker Compose (dev/prod), Dockerfile, Caddy reverse proxy, shell-script automation — no CI/CD pipeline.
- **Testing**: None configured.

## What actually exists vs. what's incomplete/fake — summary

(Full detail in ARCHITECTURE-CURRENT.md and KNOWN-ISSUES.md; this is the top-line answer to "what's real?")

**Fully real and working:**
- Multi-tenant CRM/lead/campaign/content/SEO/social CRUD (all backed by real Prisma models and either the generic CRUD factory or bespoke handlers).
- Custom auth/session system, tenant isolation on the majority of routes (with specific gaps, see below).
- Multi-LLM aggregator (Groq/Cerebras/OpenRouter/Mistral/HuggingFace) — real HTTP calls, quota tracking, fallback chain.
- Lead discovery via Serper.dev + Google Maps scraping (Playwright-based, 3-tier fallback to deterministic mock when unconfigured).
- Email sending via SMTP (nodemailer), with a console-log dev fallback.
- Crypto payments via NOWPayments (real API + signature-verified webhook) and manual wallet addresses.
- Redis-backed job queue with graceful in-memory fallback.
- Qdrant vector search with graceful in-DB fallback.
- 62/62 dashboard views correctly wired into navigation and routing — no dead UI screens.
- i18n across 29 locales with English fallback for missing keys.

**Stub / fake data (looks real, isn't):**
- 11 of 15 payment gateway integrations (everything except NOWPayments) — no real HTTP calls to the actual provider, e.g. Stripe returns a `clientSecret` containing the literal string `_mock`.
- Crypto exchange rate feed — hardcoded numbers, not live.
- Four "analyzer" endpoints (backlink discovery, competitor analysis, social analyzer, SEO crawl) — unconditionally generate `Math.random()`-based fake results and persist them to the database as if real, with no actual crawl/API integration behind them.
- WhatsApp and SMS: full CRUD data model and UI exist, but there is no outbound send integration to any real provider anywhere in the codebase — these are message-logging systems with nothing on the other end.

**Missing / broken relative to what's documented:**
- `bun run db:seed` — documented as a required setup step in `README-DEPLOY.md` and run by `scripts/dev-setup.sh`, but this script does not exist in `package.json`.
- `prisma/migrations/` — does not exist; the production deploy script (`scripts/deploy.sh`) runs `prisma migrate deploy`, which has nothing to apply against a fresh database.
- A documented default login (`admin@expload.io` / `admin123` in `README-DEPLOY.md`) does not match the actual hardcoded seed password in code (`demo12345`, `src/app/api/seed/route.ts`).
- `next-intl` is a dependency with zero usage anywhere in the code.
