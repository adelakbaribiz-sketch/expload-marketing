## 2. Known vulnerabilities (`bun audit`)

All findings below are in **build-time or dev-time transitive dependencies** (ESLint, Prisma CLI, `mdxeditor`, `mammoth`'s XML parser) — none are in a package that runs in the production request path. Real-world exploitability against the deployed app is low, but these should still be cleared on the next `bun install`/lockfile refresh since newer versions of the parent packages likely already pull fixed transitives:

| Package | Severity | Issue | Pulled in via |
|---|---|---|---|
| @babel/core | Low | Arbitrary file read via sourceMappingURL comment | eslint-config-next → eslint-plugin-react-hooks |
| @humanfs/node | Moderate | Recursive copy follows symlinks outside source tree | eslint |
| @xmldom/xmldom | Moderate | XML fragment injection | mammoth (DOCX parsing) |
| ajv | Moderate | ReDoS via `$data` option | eslint → @eslint/eslintrc |
| brace-expansion (1.x and 2.x) | **High** | Multiple DoS via unbounded expansion | eslint, eslint-config-next (typescript-eslint chain) |
| browserslist | High | Unbounded memory growth / prototype write | eslint-config-next → @babel/core chain |
| deepmerge-ts | High | Stack exhaustion on recursive merge | prisma → @prisma/config |
| defu | High | Prototype pollution via `__proto__` key | prisma → @prisma/config → c12 |
| diff (jsdiff) | Low | DoS in parsePatch/applyPatch | @mdxeditor/editor (unused package, see §3) |
| effect | High | AsyncLocalStorage context contamination under concurrent load | prisma → @prisma/config |

**None of these are in the runtime dependency tree of the deployed app** (they're all `devDependencies`-of-`devDependencies`, or transitive to build tooling / the Prisma CLI, which only runs at build/migrate time, not per-request) — this is a low-priority cleanup item, not an incident. Re-run `bun audit` after the next dependency bump to confirm these clear.

## 4. Notable dependency-usage risks (not vulnerabilities, structural notes)

- `bcryptjs` (pure-JS bcrypt) at cost factor 12 — functionally fine, slightly slower than native bindings; no action needed.
- `ioredis` connection handling is reasonable (retry strategy, credential redaction in logs); no TLS enforcement (`rediss://` accepted but not required) — acceptable given Redis isn't exposed outside the Docker network in the documented prod compose, but that compose file does publish `6379:6379` to the host, which is worth tightening independently of this dependency audit.
- No `eval()`, `new Function()`, or `child_process` usage found anywhere in `src/` or `scripts/`.
