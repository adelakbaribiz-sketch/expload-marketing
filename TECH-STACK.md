## Build system

- `next build` → `output: "standalone"` (self-contained `.next/standalone`, no `node_modules` needed at runtime).
- `next.config.ts` fails the build on TypeScript errors (`ignoreBuildErrors: false`) — good default.
- Two dev-server paths exist: `next dev` (Turbopack, default) and `next dev --webpack` (`dev:webpack` script). **Turbopack has a known, documented, unresolved bug** resolving `@prisma/client` in this project (see README-DEPLOY.md Troubleshooting) — the webpack path is the one that actually works for local development. This is a real, currently-relevant rough edge for anyone cloning the repo and running the default `bun dev`.
- `package.json build` script chains `next build && cp -r .next/static .next/standalone/.next/ && cp -r public .next/standalone/` — the `cp -r` step fails under Bun's `--shell=bun` script runner in some environments (observed directly this session) but succeeds via a POSIX shell; not a code defect, an environment/shell quirk worth a one-line README note.

## Package manager / lockfile

- `bun.lock` is present and is the source of truth. `npm`/`yarn`/`pnpm` are mentioned as alternatives in the (unmodified, boilerplate) `README.md` but the project's own docs (`README-DEPLOY.md`, `TECHNICAL_SPECIFICATION.md`) and all scripts assume Bun.

## Deployment infrastructure (as documented/scripted, not independently verified running)

- `Dockerfile` — multi-stage build.
- `docker-compose.dev.yml`, `docker-compose.prod.yml` — prod compose brings up Postgres + Redis + the app.
- `Caddyfile` — reverse proxy with automatic HTTPS (Let's Encrypt).
- `scripts/deploy.sh`, `scripts/deploy-vps.sh`, `scripts/dev-setup.sh`, `scripts/migrate-prod.sh` — deployment automation. See KNOWN-ISSUES.md for two real inconsistencies found in this flow (missing `db:seed` script; `deploy.sh` runs `prisma migrate deploy` against a repo with no migration history).

## Explicitly NOT used (per the project's own `TECHNICAL_SPECIFICATION.md`, confirmed still accurate)

- **NextAuth.js** — removed; caused Turbopack compile crashes, replaced by the custom HMAC session system.
- **LangChain** — considered too heavy; replaced by the custom LLM aggregator (Strategy pattern).
- **Socket.io** — no real-time transport; TanStack Query polling used instead where live updates matter.
